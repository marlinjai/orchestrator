# Goal

Phase 3 slice 1: let a project **connect its Instagram account** through
Instagram Business Login, so the app holds a long-lived access token it can
refresh itself. This is the prerequisite for auto-publishing (slice 2).

Do NOT build the scheduler or the publisher in this slice.

## Why it is built this way

A token can also be generated by hand in the Meta dashboard and pasted into
Infisical. That is rejected deliberately: Instagram long-lived tokens **expire
after ~60 days**, so pasting makes a recurring manual chore that will eventually
be forgotten, and publishing then stops silently. The app refreshing its own
token is the only version that keeps working unattended.

## Definition of done

- **Connect flow**, company-scoped throughout:
  - `GET /api/instagram/connect?project=<slug>` starts the dance: resolves the
    project by `(companyId, slug)`, generates and stores a `state` (CSRF), and
    redirects to Instagram's authorization URL with the scopes needed for
    publishing (`instagram_business_basic`, `instagram_business_content_publish`).
  - `GET /api/instagram/callback` validates `state`, exchanges the code for a
    short-lived token, immediately exchanges that for a **long-lived** token,
    reads the Instagram user id, and stores everything against the project's
    `SocialAccount`.
  - The callback resolves the target project from the **stored state**, never
    from a query parameter a caller can forge.
- **Token storage: encrypted at rest in the database**, not written to Infisical
  at runtime. The app's Infisical access is read-only injection at boot, so a
  runtime write is not available; the schema's `tokenRef` comment predates that
  constraint. Add the columns you need (encrypted token, expiry, obtained-at)
  and a migration. The encryption key comes from an env var; never log a token,
  never return one in a response, never put one in an error.
- **Refresh before expiry.** Instagram long-lived tokens last ~60 days and are
  refreshable while still valid. Add a refresh function and call it lazily
  whenever a token is within ~7 days of expiry. An expired token is its own
  state (`needs_reconnect`), distinct from a generic failure, so the UI can say
  "reconnect this account" instead of showing an opaque error.
- **UI on the project**: show the connected Instagram handle and token health
  (connected / expiring / needs reconnect), with Connect and Disconnect.
  Disconnect clears the stored token and sets the account back to `assisted`.
- **`status` becomes meaningful**: `auto` only once a valid token exists;
  otherwise `assisted`. Slice 2 selects its Publisher from this field.
- **Company scoping preserved.** Every new route resolves the project by
  `(companyId, slug)` from the verified session. Add the cross-company test for
  each new route exactly as the existing routes have.
- Tests, with the Graph API mocked (no network): connect redirects with the
  right scopes and a stored state; callback rejects a bad/missing/replayed
  state; the short-to-long token exchange is performed and the long-lived token
  is what gets stored; a token near expiry refreshes; an expired token yields
  `needs_reconnect`; disconnect clears it; and a user in company A cannot connect
  or disconnect company B's project.
- `pnpm test && pnpm typecheck && pnpm lint && pnpm build` all pass.
- Single commit, conventional-commit message describing the WHY.

## Notes

- The redirect URI must be registered on the Meta app before a LIVE connect
  works. Use `https://social.lumitra.co/api/instagram/callback` and record that
  in the PR description so the operator can register it; do not try to configure
  Meta from code.
- Instagram Business Login only works with **Business or Creator** accounts. A
  Personal account cannot be connected at all, so surface that specific failure
  clearly rather than as a generic OAuth error: it is the single most likely
  real-world failure here, and the fix (convert the account) is not obvious from
  a generic message.
- If you find that the token exchange needs the app secret at request time
  (it does), read it from env lazily so `next build` still runs without secrets,
  exactly like `src/lib/ai.ts` does.

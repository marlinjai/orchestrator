# Goal

Fix "write with us" producing no story. Make story generation asynchronous so it survives the proxy/HTTP idle timeout, introduce a real terminal FAILED state, and give the web flow a visible failed/retry state instead of a blank DRAFT. This is an ATOMIC change: the API and the web client that consumes it must land together (a half-merge breaks the flow). Repo: a worktree of lola-stories.

## Definition of done

1. **Async generation**: `POST .../generate` starts the run and returns immediately; the story stays `GENERATING` (persist a `runId`/started marker). The web polls story status until `GENERATED` or `FAILED`. (If you判断 a poll endpoint is needed, add `GET .../stories/:id/status` returning status + errorMessage; otherwise reuse the existing story GET.)
2. **Real terminal FAILED state**: add `FAILED` to the `StoryStatus` enum in `packages/types` (+ Prisma enum + migration) and persist an `errorMessage`. On any clean pipeline error/timeout the story goes to FAILED with the reason, NEVER silently back to DRAFT.
3. **Self-heal**: the stuck-generation scheduler moves stale `GENERATING` stories to `FAILED` (not DRAFT), with a reason.
4. **Token ceilings**: separate the prose ceiling from the segmentation ceiling so a long story does not throw "Writer output truncated" and discard the run; degrade gracefully (keep the existing single-narrator segmentation fallback ~:907-912).
5. **Retry**: a failed story can be retried and re-runs in place WITHOUT duplicating the story.
6. **Web UX**: replace the bare `catch {}` on create with: surface the real server error; ALWAYS re-fetch story state in the catch (so a 504-after-success still shows the generated story); render a distinct "generation failed, retry" state on the dashboard/editor; surface `aiNotConfigured` distinctly when no provider is configured.

## Acceptance criteria (incl. unhappy paths)

- Happy de + en: GENERATED story with content, lands in the editor with prose.
- Long target (1500-2000 words) generates without truncation / DRAFT-reset.
- Slow pipeline beyond the proxy idle timeout still completes and the story shows (async + poll), no 504-blank-DRAFT.
- Clean LLM error/timeout -> visible FAILED state with reason + working Retry, never a blank DRAFT.
- No provider configured -> `aiNotConfigured` message on the create page.
- Segmentation fails after retry -> story still saves via the single-narrator fallback.
- No permanent stuck-GENERATING; self-heal resolves to FAILED.
- Retry re-runs without duplicating the story.
- The verify command passes (api jest for stories/scheduler/pipeline + lint, web typecheck + i18n:check).
